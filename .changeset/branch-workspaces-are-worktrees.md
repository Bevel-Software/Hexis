Branch workspaces share one repository. Every branch of a knowledge base used to get a full clone on the server, the whole history copied once per branch: 142 branches took 60 GB on Bevel's own knowledge base, and every clone fetched on its own. Now a deployment holds ONE repository per knowledge base, with the objects and the remote-tracking refs, and every branch workspace is a `git worktree` of it, at the same path as before (`<workspaces>/<branch id>/<kb folder>`), so everything that reads or writes files by path is unchanged. Opening a branch copies no history, one fetch per freshness window serves every workspace, and deleting a workspace removes and prunes its worktree and nothing else.

The repository lives under the backups root (`<backups>/.kb-repository/<kb folder>.git`), which every shipped compose file already mounts as a persistent volume: no compose change is needed. A deployment whose own compose file does not persist the backups root must, or a redeploy loses the repository while keeping the worktrees, which are then recreated from the remote (commits that were never pushed are lost with it). On hexis-cloud every tenant has its own backups root, so one repository per tenant.

Upgrading converts the full clones an earlier release left at boot, one at a time: a clone's branch tip — commits the remote lacks included — is imported into the repository first, and only then does the worktree replace the clone. A clone that cannot be converted (uncommitted changes in it, objects that cannot be read) keeps working as a clone, is logged by branch, and is tried again at the next boot. Files git ignores in a clone are copied into its worktree before the clone is removed. Its stash entries and its other local refs (other branches, tags the repository lacks) are kept in the repository under `refs/kb-converted/<workspace id>/` before the clone is removed. No branch loses a commit.

When the knowledge base's repository address changes to another repository, the repository and all its worktrees are set aside together, into the same `replaced-working-copies` folder clones went to; nothing is deleted.

Git operations on two different worktrees run side by side, as two developers' worktrees of one repository do: git locks the refs, `packed-refs` and the object store, and the repository waits ten seconds for a `packed-refs` lock instead of git's default one. What the application serializes is only what git does not: the making of the repository, every write to its one config file (git refuses a second writer rather than waiting), changes to its worktree list (a prune beside another branch's `worktree add` can take the entry being made), and the moving of its folders. Each of those is a short step, with one exception: the making of the repository itself, which fetches the whole history once, and which the first operations on a fresh deployment wait for. A push, a commit, a merge or a read in a worktree never waits for any of them; a fetch of the repository waits only for the administration in progress, if any, before it starts. A push stamps its upstream after the push instead of with `-u`, so the config write is one short step. Automatic garbage collection is off on the repository; the startup phase collects once per boot, when nothing is served.

The in-app agent's internal shell tool, `execute_command`, is removed. A command line an agent composes could reach what every worktree shares (other branches' refs, the object store, the worktree list), and no reading of a command line can promise what the shell will run; so there is no tool that runs one, and no guard in its place. Every git operation an agent needs is a platform tool with fixed arguments (branches, change requests, merge, files, grep), run by the application. A call to `execute_command` by name now answers as an unknown tool.

Rolling back to an earlier release needs the workspaces volume cleared first: that release does not recognise a worktree and would treat each as a clone. Unpushed commits stay in the repository folder under the backups root, which a rollback leaves in place.
