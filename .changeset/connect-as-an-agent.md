Connecting an MCP client offers a choice of what to connect as. The OAuth consent step shows **Connect as** before the person approves: **Everything** (selected by default, and exactly the surface every connection had until now) or any `.agent` file on the default branch the person may read, by name with its description. Creating a connection key on the External agent access page offers the same choice. The choice is stored on the connection (`agent_connections.agent_path`) and on the key (`api_tokens.agent_path`), null being Everything (migration `0020_agent_path`, which also carries the choice on `oauth_auth_codes` from Finish to the token exchange), and is shown beside each key and in the Audit log's rows. A connected `.agent` file narrows the connection by its lists — `plugins:` (each plugin's connectors and skills, and the skills it links), `skills:` (skill folders), `connectors:` (`.tool` files and MCP server definitions), `platformTools:` (the platform's own tools by name; absent is all of them) — each entry a knowledge-base path where a folder means its whole subtree; `harnessTools:` is the runner's and the platform ignores it. The file is re-read through the person's read gate whenever a surface is built, so an edit reaches its connections at the next catalog revision without a reconnect, and a list can only take away from what the person may read, never add to it. `tools/list`, `tools_info`, `list_skills`, `get_skill`, `prompts/list`, `list_tool_setup`, `list_local_tools`, the agent guide and the handshake text all follow the narrowed surface; a call to a platform tool outside it is refused at its route (`403`, code `not_available_to_connection`) and the MCP proxy refuses any other off-surface tool with the same sentence, naming the agent. A chosen file that is gone, no longer readable or not a valid definition makes the connection load nothing, with one sentence saying why (in `tools/list`'s `_meta`, every call's answer and the handshake), never Everything. New in the backend: the `modules/agent-scope` module (`AgentScopeService`, `ConnectionScope`, `resolveConnectionScope`), `GET /api/mcp/agent-choices`, `agentPath` on `POST /api/mcp/external-api-keys` and `POST /api/mcp/oauth/complete`, optional narrowing arguments on `ISkillService` and `IToolManualService` reads, and an optional `connectionScope` on `ToolContext`. New knowledge bases get `Agents/README.md`, which documents the file's keys and the connect-as behaviour.
