Upgrade notes for the batch-write and archive changes in this release, for code that imports from `@bevel-software/platform-core-backend/modules/*` or calls the routes and tools named here.

- `PathHeldError` is a new export of `modules/kb-fs`. The lock-aware filesystem (`LockingFilesystem`) throws it when another holder keeps a path's lock past the retries; nothing of that write was written. It carries `path` and `holderName`, and its message names the path and its holder and says nothing was written ("Skipped editing … — locked by …. Nothing of this write was written; try again later."; it used to end "Continuing with other edits; try this one again later.", which was wrong for a batch that wrote nothing). It is a `VersionControlDomainError` with status 409 and the payload `{ kind: 'path-held', path }`, so a route or tool that passes it on answers a held lock as a 409 with that body, where it used to answer a 500: the agent tools that write through that filesystem (`write_file`, `write_files`, `edit_file`, `delete_folder` and `apply_file_upload` among them) now do. `POST /workspace/:id/unzip` and the `unzip` tool answer a held lock with the same 409 and payload, in their own sentence ("… so nothing was extracted. Try again once they are done."). Code that tests `instanceof VersionControlDomainError` before it tests for a held lock now meets this one there; test `PathHeldError` first to answer it in your own words, as the starter-pack route now does.
- `ArchiveRefusedError` is a new export of `modules/workspace/workspace.service.js`: an archive refused whole, with nothing written and no lock left held. `POST /workspace/:id/unzip`, the `unzip` tool and `apply_file_upload` answer it with a new error body, `{ kind: 'archive-refused', entry, error }`, where `entry` is the workspace path (or, when it has none, the name in the archive) of the entry that decided it. Its status is 422 for a `roles.yaml` or groups file at the repository root, and, for one of the archive's own access rules that cannot land, the status of the refusal that stopped it (422 when that refusal has none).
- `archiveEntryJudge` is a new export of `modules/workspace/workspace.tools.js`: the one `ArchiveEntryJudge` that both unzip doors and `apply_file_upload` use.
- `LockingFilesystem.writeFiles` takes a fifth, optional parameter, `refused(path, err)`, asked when taking a write's lock throws (the lock's own gates refusing that path, or the lock service failing): returning drops that write and the batch goes on, throwing refuses the whole batch with nothing written. Without it, such a throw refuses the batch, as before. The method is now generic over its content type (`writeFiles<C extends FileContent>`), so `check` is handed, and returns, writes of the caller's own content type.
- Every `writeFiles` batch now renews the leases of the locks it holds (`heartbeatLock`) every third of the lease it was granted (every 20 seconds with the lock service's 60-second lease) until it gives them back, whoever calls it, downstream callers included. A batch that finishes within a third of a lease renews nothing. A longer one sends one heartbeat per held path on each renewal, one path after another, and the platform's `heartbeatLock` logs one info line per path per renewal (and warnings when one fails), so a large batch adds lock-service traffic and log lines. A renewal that fails is logged and nothing else: a lease that lapses meanwhile is not detected.
- `platformFileUploadRefusal` in `@bevel-software/platform-shared` is deprecated: nothing refuses with it any more. It stays exported.
