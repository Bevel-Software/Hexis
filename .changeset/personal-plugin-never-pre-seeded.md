Nobody can set up a person's personal plugin folder before they have. A write into a `Plugins/personal-<id>/` folder that has no `access.md` yet is refused for every caller, an Admin included and the `access.md` rescue too, in any casing of the folder name, and a change request that would land such a write is refused when applied, with or without an approval bypass; only the owner's `my_plugin` creates the folder. A refused `mkdir` no longer leaves its directories on disk, and a folder that holds no file at all (empty directories only) is not treated as already there: `my_plugin` clears it and creates the folder as new, with its `plugin.json`, answering `created: true`. When `my_plugin` finds the folder already there and open to anyone besides its owner, as the access rules resolve it (inherited rules included, so a missing or unparsable `access.md` counts), it rewrites the rules to the owner-only template a new folder gets, commits that, and answers `repaired: true`. The folder's other files are left as they are. The template no longer suggests sharing the folder, since the next `my_plugin` call takes any other name back out.
