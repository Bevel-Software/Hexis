Sharing a file that cannot carry frontmatter no longer corrupts it. A file-level grant, revoke or restriction used to splice a YAML block into the file itself, so sharing a PDF or a presentation left it with a blank preview (and the grant never applied). Per-file rules now exist only on the files the access resolver reads rules from (Markdown notes, `.md`, and `.tool` definitions, plus any extension an overlay registers), and only while their content is text: on any other file grant, revoke and deny-here answer 422 with `{ error: "This file's access comes from its folder. Manage access on <folder> instead.", kind: "folder-governs-access", folder }`, and the file is never opened for writing. A binary saved under a note's extension is refused before the file is locked, so sharing one right after uploading it leaves the upload in place. `GET /workspace/:id/access` reports `governedByFolder` for such a file, and Manage access on it shows the same sentence with a button that opens the folder's sheet, while still listing who can open the file. Which files carry frontmatter is decided by `canCarryFrontmatter` from platform-shared; the dialog follows the server's `governedByFolder` once the view has loaded. Files already damaged are not repaired; restore them from history.
