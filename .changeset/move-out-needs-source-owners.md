A change request that moves a file out of a folder is gated on that folder's owners, as a deletion there is. A moved file's approvers now include its previous path's eligible writers, shown to a viewer who may read that path, and it counts as approved only once each end that has approvers carries a current approval from one of its own. Approving it (the `files/approve` route and the agent tools that call it, and the `viewerCanApprove` flag the app's approve and apply controls follow) takes write on the previous path too — or that path has no approvers, or one of them has approved the current head, and the person may read it; write on the previous path alone also lets a person approve, for that end. Apply (and Update) is offered only when the person's approvals would finish every file: a writer of the previous path alone gives that end's consent, not the new path's. The merge gate binds a moved file when either end has approvers, and a saved apply refusal is shown only to a reader of both paths of each moved file. So a person who may write only the destination can no longer approve and apply a move out of a folder they may not write. Closing or editing a request on the strength of writing every file it changes now counts a moved file's previous path among those files.
