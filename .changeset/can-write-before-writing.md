`list_skills`, `get_skill`, `list_files` and `read_file` report `canWrite`: whether the caller may commit a change to that path directly on the default branch, under the default branch's current access rules. The verdict is the same when the call reads a draft. `list_skills` judges each skill's `SKILL.md`; `get_skill` is `true` only when every file of the skill may be written (a bundled `file` is judged on its own); `list_files` judges a file entry by that file and a folder entry by whether a file may be added directly inside it; `read_file` judges the file read (none for a `__tool_chain_spill__` ref; for an image the verdict is in the note). A read-only credential always gets `false`, and a verdict that cannot be computed is `false`. Verdicts are computed per caller with one batched check per call, never stored in the shared skill catalog, and not part of the catalog fingerprint. The four tool descriptions and the agent guide's "Direct writes vs change requests" say that `canWrite: false` means a branch and a change request, and point to `file_stat` with `explainAccess` for why and who can approve. `merge_branch`'s description was shortened back under the 1,200-character cap.
