A tool manual or skill added, changed or removed on the default branch is visible and callable within five seconds, on the connection you already have. A commit touching a `.tool`, an `mcp.json`, a `plugin.json` or a `SKILL.md` already dropped the released catalogs whichever path made it — the app, the file tools, or a git push — and the hosted endpoint, being stateless, already rebuilt its tool surface from the live registry on every request; both are now pinned by tests, including that a manual added between two requests is in the second one's answer.

What was missing was the connection nobody can push to. The local `hexis-mcp` server registered the deployment's manual once, at startup, so a tool committed afterwards stayed invisible there until someone restarted the process. It now polls a new `GET /api/agent/catalog-revision` — a per-caller fingerprint of the tool manuals and skills the caller may read, ACL-filtered by the same services the listings use — every three seconds, and on a change re-registers the deployment's manual and sends the MCP tool-list-changed and prompt-list-changed notifications. It declares both `listChanged` capabilities so a client knows it may trust the list between them. `/api/config` advertises the route as a `catalogRevision` capability, the same mechanism agent instructions use and for the same reason: an unknown `/api/*` path on an older deployment falls through to the JWT mounts and answers 401, so a probe would tell the user to mint a new connection key over a route that is merely not there. An older deployment says so once on stderr and the server keeps its startup toolset, exactly as before. Adding a LOCAL-only server (`local: true`, or a `type: "stdio"` command) still needs a restart, because those are fetched to disk and spawned as child processes; the log line and the guide both say so.

`list_skills` and `get_skill` no longer disagree about the same skill. The listing resolved read access through the batch gate, which memoizes a file's own frontmatter rules per workspace, while loading by name resolved it through the single-file gate, which reads disk on every call — so a freshly written `SKILL.md` could be loadable by name and absent from the listing, and an author who wrote a skill and then listed them did not see their own work. Both now resolve through the one gate.

`AGENTS.md` states the five-second timeframe and the caveat it depends on: a client that caches the list it was given at connect time, rather than honouring the notification, must re-list or reconnect.
