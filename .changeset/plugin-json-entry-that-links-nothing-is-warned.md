A plugin's skill links that link nothing are now reported, on the plugin page and where a plugin.json is saved in the app. Three kinds are reported, one sentence per kind, each naming its entries in the file's order and saying what to do once: entries that are not a plain folder path from the repository root (for example one with a leading `/`, a `.` or `..` part, or a value that is not a string, named by its place in the list), which are ignored; entries that start with the knowledge base's own folder name (`knowledge-base/`), which should lose that part; and folders under which no skill the reader can read on the default branch sits. The last two are judged per reader, against the skills that person may read, so a sentence never tells anyone where a skill they cannot read is: a folder holding only such skills reads, to them, as holding none they can open, and when their catalog is empty (they can read no skill, or the default branch could not be read) no folder is reported. A plugin in the read-only bundle format gets the same sentences for its `sourceSkillRoots`, in place of its earlier "is not a folder path — ignored" line.

`GET /api/plugins` serves these sentences as `linkWarnings`, and the plugin page shows them under "Some skill links don't work"; when they explain an empty Skills band, the band reads "No skills linked. Fix the entries above." instead of offering to add the first skill. `linkWarnings` and a plugin's other definition warnings now reach only a caller who may read the plugin's folder; a caller who may only discover the plugin gets none. The app's save of a plugin.json (`PUT /api/workspace/:id/file`) answers with the same sentences in `warnings`, each `{ entry, message }`, and the file editor shows whatever warnings a save answers (a plugin.json's links, or a SKILL.md's unavailable tools) under "Saved. Some entries in this file won't work" until the next save or until another file is opened. All of it is advisory: the save is not refused, the manifest is not rewritten, and which entries link skills is unchanged. The agent write tools answer as before. The shared package adds `readSkillRoots` and `linkedSkillEntries`, which return a list's roots together with the entries it drops and their places.
