A plugin.json `skills` entry that links nothing is now reported on the plugin page and in the app's save answer. Two kinds are reported: an entry that is not a plain folder path from the repository root (for example one with a leading `/`, a `.` or `..` part, or a value that is not a string), which is ignored, and a linked folder under which no skill the reader can read on the default branch sits. The second is judged per reader, against the skills that person may read, so it never tells anyone where a skill they cannot read is: a folder holding only such skills is reported to them as holding none they can read, and when their catalog is empty (they can read no skill, or the default branch could not be read) no folder is reported. On the plugin page these lines are among the `warnings` of `GET /api/plugins`, which now reach only a caller who may read the plugin's folder (its other definition warnings included); a caller who may only discover the plugin gets none. The app's save of a plugin.json (`PUT /api/workspace/:id/file`) answers with both kinds in `warnings`, each `{ entry, message }`. All of it is advisory: the save is not refused, the manifest is not rewritten, and which entries link skills is unchanged. The agent write tools answer as before. The shared package adds `linkedSkillEntries`, which returns a manifest's linked roots together with the entries it drops.
