A plugin.json `skills` entry that links nothing is now reported on the plugin page and in the app's save answer. The plugin page (the `warnings` of `GET /api/plugins`) lists each entry that is not a plain folder path from the repository root (for example one with a leading `/`, a `.` or `..` part, or a value that is not a string) as ignored, and each linked folder that holds no skill on the default branch as linking nothing; a plugin in the read-only bundle format gets that second line for its `sourceSkillRoots` too. The app's save of a plugin.json (`PUT /api/workspace/:id/file`) answers in `warnings`, each `{ entry, message }`, with the entries that are not such a path and the linked folders that hold no skill the saver can read on the default branch. It is judged against the saver's own skills so that it never tells anyone where a skill they cannot read is; a folder holding only such skills is therefore reported to them on the save, and not on the plugin page. All of it is advisory: the save is not refused, the manifest is not rewritten, and which entries link skills is unchanged. The agent write tools answer as before. The shared package adds `linkedSkillEntries`, which returns a manifest's linked roots together with the entries it drops.
