The sidebar asks before it deletes or moves. Delete opens "Delete <name>?" — for a folder, "Delete <folder> and its N files?", or "Delete <folder> and everything in it?" with the visible count when the caller's read rules kept entries out of that folder, since the delete takes files the tree could not count — and Cancel leaves it alone. Dropping a file into another folder opens "Move <name> to <destination>?", followed by what the move does to access: who loses and who gains the ability to open or edit it, or "Nobody's access changes." — and, when that could not be worked out in time, the older sentence "Access to it will follow <destination>'s rules from now on." with a note saying so. Dropping a folder asks the same question with that older sentence alone: the lookup is per file and is not run for a folder. A warning is added when one applies: the destination is a folder you can't write (the move will be refused), or the move crosses from one root folder into another. A platform-managed file (`AGENTS.md`, `roles.yaml`, `access.md`) does not reach the dialog — the tree refuses the drag itself and says why — except a misplaced one an admin is putting back where the platform reads it, which is the one move of such a file that is allowed. Nothing is sent until Confirm; Enter confirms, Escape cancels, and focus returns to the row. A refused move now says so instead of failing silently.
