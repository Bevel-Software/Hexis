A card's name now keeps a readable width and its badges wrap under it when the row runs short. The report was a tool card reading "di…": the name was `truncate` and the badges beside it (`MCP server`, `Linked`, `Owner`, `Deprecated`) were `shrink-0`, so the whole of a 236px card's shortfall came out of the one part of it anybody was reading, and four pills that each said less than the word they had crowded out kept every pixel they asked for.

The name now has a floor of 12 characters while badges are beside it, and the badges break onto a second line rather than take it. Below that floor nothing changes: the name still truncates with an ellipsis, still carries its full self in `title`, and is still in the DOM whole, so a screen reader reads all of it either way. A wide card is the card it always was — name and badges on one line. Which badges appear is untouched; the only thing that moves is where they sit when there is no room. Measured in chromium against the production stylesheet: on a 200px card the badges take a second line and the name keeps the first one whole, and from a 339px card on they share one line again.

The floor is spent on badges and on nothing else, which is the correction this change needed. A floor is a claim on space that something else has to give back, and a badge is the only thing on such a row that can — it moves. A logo cannot, and a page header's back link is not even part of the name's row, so a floor granted against either is a minimum width with no matching concession: the row simply becomes wider than the box it is in. Granting one for a logo is what briefly sent the tool page's title outside its own title bar at every phone width, since that bar is exactly as tall as the sidebar header row beside it and has no second line to give.

One component, `NameWithBadges`, is what all three surfaces spend: the library card, the plugin index row and the tool page header. The plugin row gains a `title` it did not have — it used to pass its label through as a bare string, so a plugin whose name the row had to truncate had nowhere to finish saying it. The tool page header takes the truncation and the `title`, and says in its markup that its row may not wrap, so the day a badge is added there the band clips rather than quietly growing.

A plugin row can now run short at all, which it could not before. `ItemMenuFrame` lays each card and row out in a grid whose implicit column was `auto` — a track whose minimum is its content's min-content, and the min-content of a row holding a `whitespace-nowrap` name is that name at full length. `min-w-0` does not reach that; it bounds the grid box, not the track inside it. So a row wearing a 60-character name laid itself out 605px wide inside a 200px column and hung out of it whatever the window did, long before this ticket. Flooring the track at 0 makes the row the width of the column it is in, which both removes that overflow and gives the badges a shortfall to react to. Cards are unaffected, measured: `CardGrid`'s track already carries an explicit minimum, so a card was never sized by its own min-content.

jsdom has no layout, so the tests pin the contract the layout is made of rather than pixels: the floor, the `flex-1` that makes flexbox measure the name AT the floor when it picks a line break, the `flex-wrap` that gives the badges somewhere to break to, the `shrink-0 max-w-full` that moves the badge group as a unit without letting it out of the row, and the grid track that lets the row be short in the first place. The three awkward names are covered — a 60-character name on a card, on a row and on the page header; a missing name, which opens no empty tooltip; and two tools of the same name in different plugins, which stay separately addressable and keep their own foot notes.
