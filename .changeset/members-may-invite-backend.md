Anyone signed in can invite people. A new signed-in route, `POST /api/invitations` with `{ email, role?, startingPassword? }`, creates a NEW account only: an address that already has one answers `{ status: 'existing' }` and nothing is written to it (no password, no role), whoever asks. `role: 'admin'` is refused with 403 unless the caller is an admin. The starting password is generated on the server (16 letters and digits without 0, O, 1, l and I, from `crypto.randomInt`), stored only as its hash, returned once in the answer and never logged: always where password sign-in is on and no single sign-on is offered, on request where both are on, and never where password sign-in is off (a request for one is refused with 400). The account-invited event carries the generated password as `startingPassword` beside `passwordSet`, so a deployment's listener can put it in the invitation it sends. The admission port is asked with the new reason `invite`; a refusal answers 403 with `kind: 'admission'`. Each created account writes one `account audit:` line with `action: 'invite'`. `POST /api/admin/accounts` is unchanged and stays admin-only.
