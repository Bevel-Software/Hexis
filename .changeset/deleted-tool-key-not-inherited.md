A tool's stored keys now go with the tool when its definition leaves the catalog by any route, not only when it is deleted from its tool page. When a scan of the default branch no longer finds a manual's name declared (its `.tool` file deleted, its server dropped from `mcp.json`, its id changed), the values stored under that name are wiped the same way a delete from the tool page wipes them. A later tool that reuses the name then starts with no shared key: the old value is not shown as set and is not sent. A rename or move that keeps the id keeps its keys. A scan that could not see every declaration wipes nothing. That covers a folder or `.tool` file it could not read, an `mcp.json` that does not parse as a server map, and a refused `.tool` that names no manual. A refused edit that still names its manual keeps that manual's keys. A removal is noticed only once the running server has completed one scan to compare against. A tool removed while the server was down is not noticed after the restart.
