Deleting a branch, whether by hand or as the automatic retirement that follows a merge, now refuses while any open change request still needs it, including one proposing *into* it. A change request names two branches and needs both, but every guard asked only whether the branch was some request's source, so merging `X -> main` retired `X` out from under a second open request targeting `X`. That request then became unusable in every direction: its detail read resolves the target before the source and failed with `unknown branch`, so it could not be read, declined, or deleted, and the start-up sweep that closes requests whose branch is gone also looked only at sources, so it survived every restart. The sweep now closes a request when either end is missing, which retires the ones already stranded, and it also runs on demand: a delete or decline that fails in a way that may mean a missing branch kicks the sweep, so a request stranded mid-uptime is cleared without waiting for a restart. The refusal message now distinguishes the two directions, since a request proposing into a branch is not the branch owner's to withdraw.
