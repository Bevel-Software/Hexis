In an access rule, a bare principal name means the role when a role of that name exists, and the group otherwise; `role/<Name>` always means the role and `group/<Name>` always means the group. A group named `Admin` can therefore no longer inherit the Admin role's grants, and a bare denial denies the role exactly as a bare grant grants it — the group is denied as `deny group/<Name>`. Existing bare spellings still parse. The Manage access dialog and the access API (the control service, the mutation service, the routes, the access view, the groups and roles admin) now write `role/<Name>` and `group/<Name>`, never a bare name; a revoke never crosses from a role to a group or back, canonicalises a spaced prefix, and stays exact for a role when the principal model fails to load.

**Migration:** a name shared by a role and a group now resolves bare to the role. The groups roster answers `bareNameResolvesToRole`, and the reference scan — reading rules with the resolver's own parse and walk, injected from the composition root, so a file `.bevelignore` hides is still found — names every `access.md` whose bare group name now resolves to a role; the Groups & Members page lists them with the rewrite for each (a grant row as `group/<Name>`, a deny row as `deny group/<Name>`) so an Admin can fix them. A group rename rewrites every candidate, hidden files included, through the full parser's structural rewrite (quoted, flow-YAML and anchor-aliased forms), and refuses closed only when a reference survives a form it cannot rewrite; an unlistable folder or unreadable candidate is logged and skipped, never cached. Rename refusals and the rosters name only files the viewer can read: a rename blocked by content the viewer cannot be shown refuses with one message carrying no path, count or YAML form (the server log names the place), and rules in unreadable files are left out of the rosters rather than counted, so a delete confirmation never claims nothing is shared when unreadable rules may exist. The agent guide's principal paragraph states the rule, its examples and the starter packs' `access.md` comments use the prefixed forms.
