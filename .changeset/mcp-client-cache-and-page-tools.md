The hosted MCP server keeps one tool client per person until their catalog changes, and an HTML page on the app's file page calls the viewer's tools through `window.bevel.tools`.

The server no longer rebuilds a person's tool client on every request: it builds one per person, caller kind, key scope and catalog revision (the fingerprint `hexis-mcp` already polls) and reuses it until a `.tool` they may read is added, changed or removed, until one of their secrets changes (a shared one: everyone's), or until it sits unused for an hour; at most 500 are held, the least recently used dropped first. A warm request answers in the time of the request alone, where a slow knowledge base used to show clients "tool discovery failed: timeout". The cached client carries no request's bearer: each request's own key or minted token is read at call time, so per-key metering and audit stay per key, a revoked key is refused on its next request, and a page kept open for a day keeps working. Tool definitions are held once for every client that discovered the same ones, so hundreds of warm clients cost one catalog's worth of memory. A restart is still invisible: the first request after it builds.

On the app's file page an HTML page gets `window.bevel.tools` — `searchTools(query)`, `toolsInfo(names)`, `callTool(name, args)` and `callToolChain(code)` — answered over the hosted MCP server as the viewer: the same tools, answers and refusals the viewer's agent gets, and never the enterprise agent's internal tools. Reads run at once; the first call that may write (a tool tagged `write`, a tool the manual does not list, any chain) shows the app's card "<page> wants to write to the knowledge base" with the page's path, Allow while open or Deny, and Allow holds until the page is reloaded. On the embed, a skill page or any other preview the member is `null`, and `window.bevel.requireTools()` offers Continue without tools or Open in the platform. Every call a page makes is in the Audit log under the viewer, with the page's path as the agent; a denied call is recorded as refused (migration `0018_agent_events_page`). The agent guide's HTML views section documents the member.
