A file's renderer fills the browser window on request. The file page offers **Full screen** beside the file's other actions — in the pane bar for a prose document, in the page header for a full-bleed one — for every file it renders, in read and edit mode alike, and a file URL asks for the view directly with `?fullscreen=1` (on a node-id URL and a path URL alike; the id canonicalisation keeps the query, and a reload keeps the view). Entering and leaving replace the history entry rather than adding one. While filling the window one control at the top right, "Exit full screen", returns to the page, and so does Escape, through the modal layer, so a dialog opened on top takes Escape first. The view is the file page's, not the renderer's: the read pane that already holds the renderer changes its layout, so the renderer is never remounted — unsaved edits, an HTML page's state and its tool bridge survive both ways — and a renderer a deployment registers gets the view without knowing it exists. The embed surface, the change-request file preview and the history preview are unchanged.
