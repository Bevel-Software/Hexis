Agents can download knowledge-base files through one-time links. The new `request_file_download` tool takes a branch and a list of files and folders, judges every file on its own against the caller's `read` and `download` rules (a folder's files included), and answers a link per included file — its bytes with its own content type — plus, per requested folder that kept at least one file, a zip of its included files at their full repository paths, which `apply_file_upload` at `knowledge-base/` puts back. Each link (`GET /api/agent/downloads/:token`, or the bare address with an `x-download-token` header) answers once, for 15 minutes; the manifest carries each file's size and SHA-256, and lists every refused path with why — `not found`, `download permission required`, `the folder holds no files`, or the deployment's read hook's own words. A file inside a requested folder that the caller may not read is left out without being named, as the explorer leaves it out; only a path the caller named is answered `not found`, a folder holding nothing they may read among them, as the explorer hides such a folder. The file limit counts only what they may read. A request may total 500 MB (its files once, and its folders' zips together) and 10,000 files, and a user holds at most 10 open requests. Every included file goes through the agent-access read hook, a read-only credential is refused, and a read-only deployment still serves downloads.
