An agent connected over OAuth is no longer asked to re-authorize every day or two. Refresh tokens are rotated on use, and a client that refreshes from two places at once (Claude's hosted apps refresh before expiry and again on a 401, and a scheduled task refreshes beside the chat that shares its connector) presented the same token twice; the second presentation was refused as invalid, which the client took as a dead credential. A refresh token rotated within the last 60 seconds is now honoured once more with a fresh pair on the same connection; past that window, or after a revoke, it is refused as before. The old pair's access token also keeps working for its own hour after a rotation rather than dying at once, so a runner mid-task is not cut off by a refresh another runner made; a revoke, a sign-out, or that one allowed replay of its refresh token still ends it immediately. Every refused refresh is now logged with its reason (unknown for this client, revoked, already replayed, rotated how long ago, expired, a widened scope, the agent revoked, or changed by a concurrent request), never the token. The clean-up of expired token rows that rides on every mint runs before a refresh opens its transaction, so a burst of refreshes never waits on the connection pool for it. Adds a `rotated_at` column to `oauth_tokens`.
