An in-app link inside a rendered file that leads to another file or node opens its target in a new tab: a Markdown link in a page, a link in the frontmatter panel, a node-id link, and a link written in an HTML page (through its link bridge, and the page's "Open in the platform"). The new tab gets the target's plain address, and the tab the reader was on keeps its location, its scroll and its full-screen view. A link to a section of the same file still scrolls in place, keeping the tab's own address and query; an external link is unchanged. The rule lives in the file-nav hook (`useFileNav().openLink` and its new `linkTarget`, `useNodeIdNav().openNodeId` and its new `nodeIdTarget`), and the Markdown pipeline renders each in-app anchor from the same answer: its `href` is the address the click opens, with `target="_blank"` and `rel="noopener"` when that is a new tab, so a middle-click, the context menu and a screen reader agree with the click, and a modified click is left to the browser. With a resolver the pipeline now takes every workspace destination, not only `.md` links, so a link to an HTML page or a PDF no longer replaces the page as a relative URL. A node-id link opens its id URL directly and the new tab resolves it, rather than resolving first and navigating. A link in a skill's file on its library page follows the same rule (resolved on the default branch, where skills live, for a Markdown file and an HTML page alike), and so does that page's "Open in the platform". A link to a section of the page it sits in scrolls that page where the address cannot: inside an HTML page's frame (`Roadmap.html#q3` from Roadmap.html scrolls as `#q3` does), and in a skill's file on its library page. A modified or middle click on a section link is left to the browser too, and an id-link to the node on screen stays in place even while the tab is still on the file's path URL. A tab the browser refuses to open is reported in the console. The sidebar tree, open tabs, search, breadcrumbs and the library's own links navigate in place, as before. The agent guide's HTML views section says so. The workspace module now exports `useFileNav`, `useNodeIdNav`, `KbLinkTarget`, `OpenLinkOptions`, `PageLinkHomeContext`, `scrollToHeading` and `stripJunkBeforeKbDir` from its index, for the library and review modules that follow the same rule.
