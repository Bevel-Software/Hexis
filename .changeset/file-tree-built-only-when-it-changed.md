A save that cannot change the file tree no longer makes every open tab fetch the whole tree. Until now every write was announced with `file-changed` and `fs-tree-changed`, and the web app asked for the tree on each, one request per event per tab; on a branch where agents save every few seconds the server spent much of its time building trees for answers nobody read.

Both events can now carry `listingUnchanged: true`. The sender sets it when an existing file's content changed, nothing was added, removed or renamed, and the file decides nobody's access: not an `access.md`, the roles or groups files, a plugin manifest or a `.bevelignore`, and the file's own leading `---` block is the same as before. A commit of one file reports this as `CommitAttribution.contentEdit`, told from the status git already answers; for a file that can carry access entries it costs one read of the version it replaces. A commit whose push had to pull first, and a file an unzip put on disk before its lock, are announced without the mark. The web app keeps its tree on a marked event, and unmarked events share their tree requests: one at a time, and whatever arrives while one is under way is answered by one more after it, so a burst costs a request per request's length instead of one per event. A request that has not answered after a minute no longer holds the next one back. An event without the mark means what it always meant, so a batch write, an upload, a move, a delete and a sync are announced as before. The server's own listeners of `fs-tree-changed` are unaffected: the event is still emitted for every write.

The workspace service lists part of a tree. `listFilesUnder(workspaceId, path, { depth, readFilter })` answers one folder's subtree exactly as the whole tree holds it, read filter and `.bevelignore` rules included, by walking that folder alone; `depth` cuts it, and a folder at the cut has no `children`. `listFilesToDepth(workspaceId, depth, readFilter)` cuts the whole tree the same way. `IWorkspaceService` gains `listFilesUnder(workspaceId, path, { depth })`, without the read filter, which is the service class's own option; an implementation of that interface outside this repository must add it. The list of access rules inside a folder now asks for that folder instead of the whole tree.
