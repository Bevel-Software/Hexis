The agents' `grep` tool searches with ripgrep. A search over a workspace of 11,000 files no longer reads every file through the server's main thread: `rg` child processes search the tree in path order, each given only files already judged readable for the caller (a file the caller may not read is never opened), and the search stops once `max_results` lines are found or the caller goes away, and ripgrep stops matching a file at the lines the answer can still take, so one log of millions of matching lines does not use up the budget. A search takes a fraction of a second and the server keeps answering everyone else while it runs. The answer keeps its shape and caps (`{ matches: [{ path, line, text }], truncated, note }`, 1-based lines cut to 300 characters, `max_results` default 200), and its matches now come in path-then-line order. It covers every text file under `path` that the caller may read, hidden and git-ignored files included. It never enters `.git` and never follows a symbolic link, and a file the caller may not read never contributes a line. Office, OpenDocument, PDF and email files are still searched through their extracted text, under the same per-call extraction budget. A `path` naming one text file is searched by ripgrep too, so it answers the same lines a search of its folder answers from it, and a folder named with a trailing slash answers paths spelled once (`a/b.md`, not `a//b.md`).

Patterns are ripgrep's default engine's: RE2-style, with no look-around and no backreferences. A pattern the engine refuses is answered with a 400 (`invalid_pattern`) quoting its reason, and the tool's description says which patterns it takes. A search still stops at 5 seconds with the 400 `pattern_too_expensive`. The 5 seconds include the time spent judging which files the caller may read. That check now reads a file only as far as its frontmatter, so judging a tree of large transcripts reads a line of each rather than every byte. The first search after a commit (which clears the access cache) is as fast as any other, and the explorer tree and every other batched read check get the same saving. A file too large to read whole now has the access rules in its frontmatter honoured, where before they were missed.

**New runtime requirement:** `rg` must be on the server's PATH. The server refuses to start without it, the way it refuses a git that is too old. The Hexis Dockerfile installs Debian's `ripgrep`; an image built from another Dockerfile must add it (`apt-get install ripgrep`).
